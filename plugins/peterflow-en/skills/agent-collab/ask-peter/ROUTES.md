# Choose an entry point

| Starting point | Next step |
| --- | --- |
| A bounded change with clear acceptance | `plan → implement`. Continue directly from a usable short plan. |
| Dependent tasks in one implementation context | `plan → tasks → implement`. Resume at the existing plan or ready task. |
| Independent implementation, review and test contexts | `plan → tasks-pro → implement-pro`. The last skill includes review, testing and final integrated acceptance. |

A new chat alone does not make the work large. Select the independent route when there are real phase outputs to hand off and the host can supply separate executors.

| Need | Skill |
| --- | --- |
| A design or task list might miss an outcome | `analyze` walks a concrete scenario through the sources. |
| Code exists and needs a standards and requirements review | `code-review` examines the named diff or current files. |
| The feature seems done but acceptance is unclear | `converge` follows goals into the current implementation and evidence. |
| An earlier product decision has changed | `feature-retcon` reconciles affected layers and journals authorized writes. A missed task under an unchanged goal stays in its original list. |
| A failure or slowdown needs a cause | `debug-expert` builds a reproducible failure and tests competing explanations. |
| One module needs a better interface | `design-mod` examines actual callers and seams. |
| The user wants candidates across a codebase | `review-arch` produces a before/after report, then explores the selected candidate. |
| A technical fact or trade-off needs investigation | `research` resolves it against primary sources for the target environment. |
| The user wants to learn | `learn` teaches one lesson or prepares a complete course after agreeing on its roadmap. |
| An explanation or English draft needs clearer language | `plainly`. The standalone message “Plain English, please” restates the last answer. |
| Instructions are intended for an agent | `writing-for-agents` checks triggers, reading paths and completion criteria. |
| The user wants to learn from a real development session | `retro` proposes improvements verified against today's workspace. |
| Shared rules need initialization, drafting, adoption or checking | `maintain-standards` selects the relevant action. |

**Continue in this chat.** Use `quickstart` when asked to sync a feature's context or update its handoff page. It follows a stale next step to the latest evidence.

**Move to a new chat.** Explicitly invoke `context-handoff` to send a minimal packet and verify receipt. The receiving chat's first turn acknowledges it and waits. Scoped context for an already-authorized subtask can travel through its existing channel. A change of phase alone does not require a fresh user chat.
