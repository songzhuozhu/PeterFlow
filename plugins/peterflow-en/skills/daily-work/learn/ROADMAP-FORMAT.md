# Agree on a roadmap and prepare the full course

Start from what the learner wants to do and what they already know. Reuse an existing mission, learning records and any outline the learner supplied. Ask only questions that change the starting point, scope or difficulty.

Propose a short ordered sequence in conversation. Each lesson has one topic and one observable outcome. Explain real prerequisites. Let the learner skip, combine, reorder or deepen lessons. Show the revised sequence and wait until the learner confirms this version. If they already provided a final roadmap and asked for the whole course, use it directly. If they asked only for a roadmap, save the agreed version and stop.

1. Save the agreed sequence, starting point and goal as `ROADMAP.md` at the root of the teaching workspace. It doubles as the course index.
2. Prepare every agreed lesson in this pass. Reuse still-applicable lessons, sources and components. Use the next available number in `lessons/` for each new complete HTML lesson. Each lesson has an explanation, a practice with feedback, a primary source and relevant reference links. The learner can complete the exercises later at their own pace.
3. Link each actual lesson back into `ROADMAP.md` with a relative path. After interruption inspect the existing files and create only the missing or unfinished ones. Before delivery verify that each link opens and that its lesson teaches the agreed outcome. Share the index and starting lesson. Open only the starting lesson when appropriate.

The roadmap records preparation. [Learning records](LEARNING-RECORD-FORMAT.md) record demonstrated understanding, self-reported prior knowledge or other qualifying observations. Producing a lesson alone provides no evidence that its reader has mastered it.
