# Investigate a technical question

Identify the decision, version, environment and constraints from existing material. Ask only about unknowns that materially change the answer. Handle a small query in the current context. If a lookup is independent, delegation is authorized and there is other work to do, give a researcher the question, constraints and starting sources.

Trace the claim to an authoritative source. Use the specification for a contract, the locked version of source and tests for an implementation, and current official documentation for present capabilities. Cite the version or date. Search snippets and secondary articles can point to the original.

Distinguish documented behavior, code reading and actual observation. Check versions, configuration and environments before reporting a conflict. A targeted authorized experiment should record inputs, command and observed result. Evidence that a product *supports* one deployment model does not establish that it *requires* that model.

Lead with the answer. Attach a source and locator to each consequential claim. Mark inferences, conflicting accounts and evidence still needed. For a choice, compare only differences that change the decision. Keep short answers in chat. If a record is needed, prefer the requested file or existing topic and edit the relevant section. Otherwise use one Markdown note in the project's normal location, or `.peterflow/specs/<topic>/`. Research alone authorizes a finding, not implementation.
