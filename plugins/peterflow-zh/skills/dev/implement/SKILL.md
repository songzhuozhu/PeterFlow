# 实现并验证

输入为明确的目标、验收和计划或任务，不要求它们由某个 Skill 生成。交付代码、适用验证结果，以及原计划或任务的进度。

## 接续现有工作

1. 确定工作区和范围，沿项目已有规范入口读取计划引用的生效条款，新工作区默认 `.peterflow/standards/`。计划漏引相关条款或改动影响了其他调用方时，从总索引（L3）补查适用的通则（L0）、工程专题（L1）和受影响功能的现行条款（L2）。按条款及其例外实现，并从用户入口验证对应行为。候选和备份不作为验收条件。没有规范库时沿已有计划继续。
2. 检查 Git 状态、暂存区和有关代码，识别已有成果与本次改动。没有 HEAD 的仓库也可以工作；不为验证创建提交，不自动暂存、提交或推送。
3. 轻量任务直接使用简短计划，不创建 tasks.md。中等任务读取 Phase 的目标、前置与阶段验收，以及所属 Task 的依赖和验收；旧清单没有 Phase 时直接沿原任务续接，不为格式重排。缺少必要依赖说明时在原资料内补足，不要求重跑前序 Skill。遇到重型单元协议时说明所需的分单元执行能力，不把它当普通清单直接全做。

## 按依赖实现

选择所属 Phase 前置与 Task 自身依赖均已满足的工作，核对前置交付的产物是否真的可用。若前置的完成条件反过来等待本项，先按原目标澄清交付和验收的归属，无关工作可以继续。已勾选项也要对照代码与证据，保留有效成果。

先找到用户入口和可复用的实现，用能保持现有调用方行为的最小局部改动满足验收。准备加抽象、依赖、配置、兜底、文档或测试设施时，先问：“沿用现有做法，哪条要求满足不了？”遇到取舍时查[最小改动对照](references/minimal-change.md)中的对应场景。明确要求的重构、测试或文档照常交付。

改动已经扩散时，按同一对照里的纠偏办法处理：局部噪声只清理本轮差异；方案绕远就退回直接实现；连锁失败先查第一处原因。确需扩大明确范围时，说明受阻行为和最小追加改动。用户说“只改 X”就收窄到 X，说“停下”就停止写入并回报现场。

采用项目和用户要求的测试方式；没有规定时，选择能观察本次目标行为的验证。修复缺陷时先复现或建立能暴露问题的检查。无需为简单文案或格式改动编造单元测试，但应实际检查结果。

按目标选择观察入口。命令行目标用真实命令行输入，检查退出码和输出；库测试只支持所测的库行为。预期取自需求或已知样例，确认目标断言实际运行。把工作目录、命令或操作、输入和预期、实际结果、未覆盖项回填原处。轻量任务可用一句话。

修日常检查时，用项目规定的同一条命令验证两种情况：正常实现通过，在隔离副本重放原错误时目标断言失败、命令返回失败。入口已能拦住该错误就保留现状，报告实测结果。

结果需要稍后复用时，在运行当时绑定相关实现、测试、验收约定及会影响结果的配置。优先用能定位到这次输入的 CI 记录。未提交工作可在测试前对选定文件执行 `shasum -a 256 文件…`，记录工作目录和相对路径，测试后复核同一组摘要。采用项目等价命令也可。记录测试本身的退出码。若输入在运行期间变化，重验受影响项。任务文件同时承载验收条件与回执时，摘录对应条件，只对实际输入取摘要；给将要回填的整份清单取摘要会使记录立即过期。原有日志保留当时的证据，不能用今天的摘要补签。

发现需求或方案矛盾时，指出位置和影响；明确事实可直接修正原文，影响产品语义且无法确定的部分等待决定，继续无关工作。不要靠静默改验收让测试通过。

## 更新原处并收尾

- 对照进入时的状态检查本轮 diff。指出每处改动服务的需求、规范或验收，去掉能确认属于自己的多余改动，再验证保留下来的行为。
- 轻量任务把修改和验证回填原计划或会话，中等任务更新原 tasks.md 中所属 Phase 和 Task；只有完成且必要验证通过的任务才勾选，所属任务和阶段验收成立才算 Phase 完成。
- 验证优先回填原处。确需独立保存的测试或验收记录放到功能的 `verification/`，并在原计划或任务中链接该记录。
- 结果分为已完成、未完成、未验证、受阻。命令未执行、只编译成功或外部环境不可用时明确有效范围。
- 新缺口留在原计划或原任务；代码、测试或契约变化后重验受影响部分，不重复已证明无关的工作。
- 核对累计结果满足本轮目标，报告改动入口、实际验证、剩余事项与 Git 状态。此核对是实现职责，不强制调用 analyze 或 converge。

沿用已有资料和任务指定的路径。新增独立材料时，详细设计放 `design/`，参考资料放 `references/`，交付实施的 SQL、配置或操作说明放 `delivery/`，多方共用的接口或消息契约放 `contracts/`。只在实际写入文件时创建所需目录，已有权威文件直接链接。保留已有资料，不把模板复制到已有文件上。规范作为输入读取，本流程不承担规范维护。
