# MISSION.md 格式

`MISSION.md` 位于教学工作区根目录，记录用户为什么学习这个主题。接下来教什么、推荐哪些资料、安排哪些练习，都应当能从这份文档里找到依据。

## 模板

```md
# {主题}的学习目标

## 为什么学
{用 1–3 句话写出用户想在现实中实现的具体目标。掌握这项技能后，他们的生活或工作会发生什么变化？如果答案只是“理解 X”，继续追问他们想用 X 做到什么。}

## 怎样算学会了
- {用户将能做到的一件具体、可观察的事}
- {另一件具体的事}
- {……}

## 约束
- {时间、预算、已有安排、学习偏好，以及其他影响学习方式的条件}

## 本次学习范围之外
- {列出用户明确表示现阶段不想深入的相关主题，让学习保持在他们的最近发展区内}
```

## 写法

- **一个工作区只设一个学习目标。** 用户想学两件互不相关的事，就分别使用两个工作区。
- **把目标落到实处。** “在十月前跑完一次半程马拉松”比“身体更好”具体。“把一个 Rust 命令行工具交给团队使用”也比“学 Rust”更能指导选课。
- **遇到含糊的目标就追问。** 用户还说不清为什么学时，先跟他们聊清楚，再开始写。写下一个偏离真实意图的目标，会把教学带偏。
- **实际目标变化后及时修订。** 用户想做到的事变了，就更新此文件，让后续课程依据新目标安排。
- **保持简短。** 目标写到超过一屏，往往已经把实施计划也写进来了。这一页只要能指明学习方向就够了。
