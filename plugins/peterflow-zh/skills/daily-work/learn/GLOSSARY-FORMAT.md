# GLOSSARY.md 格式

`GLOSSARY.md` 规定教学工作区里各个概念的统一叫法。讲解、练习和学习记录都应沿用这里的术语。编写术语表也是学习的一部分。用户能把一个概念浓缩成简明的定义，就是理解它的证据。

## 结构

```md
# {主题}术语表

{用一两句话说明本术语表覆盖什么主题。}

## 术语

**肌肥大（Hypertrophy）**
肌肉在反复训练中受到机械张力和代谢压力刺激后出现的生长。
_避免使用的叫法_：增重、练大块头

**渐进超负荷（Progressive overload）**
随时间推移，通过训练负荷、训练量或强度，系统性地提高对肌肉的要求。
_避免使用的叫法_：更使劲、升级

**主观用力程度（RPE）**
用 1–10 分自评一组动作做起来有多吃力。10 分表示已经力竭，8 分表示还能再做两次。
_避免使用的叫法_：努力分、强度评分
```

## 写法

- **等用户理解了再收录。** 术语表用简短定义保存已经掌握的知识。刚介绍一个概念时，等用户能够正确使用它，再收进来。
- **确定首选叫法。** 同一个概念有几种叫法时，选定最合适的一种，把其余列为应避免的别称。这样后续讲解可以用一个词准确指代整个概念。
- **定义要紧凑。** 用一两句话说明这个概念是什么。用途和操作步骤留给相应的讲解。
- **用已有术语写新定义。** 一个词一旦收录，此后都优先用它，包括解释其他词的时候。这样复杂概念也更容易理解。
- **自然成组时再加小标题。** 例如 `## 解剖学` 或 `## 训练计划编排`。术语彼此关系紧密时，用一份平铺列表就可以。
- **明确消除歧义。** 如果行业里对某个词的用法比较宽泛，就写清这里采用的含义。例如“本工作区的‘组’一律指正式训练组；热身组另行记录。”
- **随着理解加深而修订。** 用户第一周写下的定义，到第六周可能已经发现有误。在原条目中更新，让它反映当前的理解。
