# 学习记录格式

学习记录保存在 `./learning-records/`，按 `0001-slug.md`、`0002-slug.md` 的顺序编号。写第一条记录时才创建这个目录。

它在教学中的作用类似软件开发中的架构决策记录（ADR）。记下会影响后续教学、但并不显而易见的体会、重要洞见，以及用户自己说明的已有知识。用这些记录判断用户的最近发展区。

## 模板

```md
# {用短标题点明学会或确认了什么}

{用 1–3 句话写出学到了什么，或确认了哪些已有知识，以及这为什么会影响后续课程。}
```

以上就是完整格式。一条学习记录可以只有一段。写清用户现在已经知道什么，以及这件事为什么会改变下一课的安排，就达到了目的。

## 可选内容

大多数记录用不到以下内容，只在它们确实有用时补充。

- **状态**。早先的理解有误、后来被新认识取代时，可在文件头的 `Status` 字段中记录状态（`active | superseded by LR-NNNN`）。
- **证据**。用户怎样表现出了理解？例如答对了一个问题、完成了练习，或讲述了以往的经验。以后可能需要复核这项判断时，证据就值得记。
- **对后续教学的影响**。可以开始教什么，或可以排除什么？这种影响不易看出时才值得专门说明。

## 编号

查看 `./learning-records/` 中已有的最大编号，新记录的编号在此基础上加一。

## 什么时候写学习记录

发生以下任一情况时，写一条记录。

1. **用户确实掌握了一项有难度的内容。** 已有证据说明他们能正确运用这个概念。这就确定了后续教学可以从哪里起步。
2. **用户说明了自己原本就知道什么。** 例如用户说“X 我已经会了”，要记下他们自述掌握到了什么程度，避免此后重复教学。
3. **用户纠正了一个误解。** 他们以往的理解有误，现在能说清楚错在哪里。这类记录尤其有价值，有助于预判他们学习相关主题时还可能卡在哪里。
4. **学习过程改变了目标。** 用户发现自己真正在意的事情与起初设想的不同。在记录中链接 [[MISSION.md]]，并更新学习目标。

### 哪些情况不记入学习记录

- 刚讲过的内容。等用户表现出已经学会的证据，再记入学习记录。
- 已经用简短定义收录在 [[GLOSSARY.md]] 里的术语。定义保留一处即可。
- 逐次会话的活动流水账。只留下足以影响教学决定的认识。

## 新记录取代旧记录

如果新记录与旧记录矛盾，例如用户加深了理解或纠正了错误，在旧记录中标上 `Status: superseded by LR-NNNN`，保留旧记录。理解是怎样一步步变化的，本身就是有用的信息。
