# 问 Peter

用户点名时，帮他们把“我现在该用什么”变成一句可以直接使用的请求。这里给的是流程建议。推荐某个 Skill 本身不会启动实施、派工或会话交接。

1. 从用户想交付的结果、已经有的材料和目前卡住的地方判断起点。已有计划、任务清单或验收回执都可直接接续。仅当缺失的信息会改变推荐时才问一个具体问题，例如“你想核对方案是否自洽，还是代码已经写完、需要核对验收？”
2. 用[流程与场景](ROUTES.md)选出最相关的候选。给出具体用法、组合顺序或建议跳过某一步前，打开候选的 PeterFlow 版 `SKILL.md` 核对输入、产物和调用边界。优先读用户指定的包。独立安装时看 `<技能目录>/<名称>/SKILL.md`。原生插件从该语言的根目录（源码中为 `plugins/peterflow-zh/`）按 `skills/<分组>/<名称>/SKILL.md` 查找。同名的其他项目 Skill 可能采用不同流程。
3. 完整安装、单项安装和宿主当前展示的清单是三件事。单独安装本导航时，仍可根据随包说明推荐方向。如果目标正文不可见，说明哪些细节尚未核实；只在实际看到安装副本时确认已安装。宿主列表未展示某一项，也可能是它只接受显式调用。

先给最合适的下一步，用用户手头的事实说明理由，再给一句可复制的调用示例。按当前宿主和安装方式写调用名，例如中文版插件在 Codex 中用 `$peterflow-zh:converge`，在 Claude Code 中用 `/peterflow-zh:converge`。一个 Skill 足够时就到这里。用户问整条流程时，再给从当前位置开始的顺序，说明什么情况才需要转入下一步。普通编辑就能完成的事，也可以直接这样回答。
